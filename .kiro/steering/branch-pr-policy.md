# Branch & PR policy

**Rule: 1 Issue = 1 PR = 1 branch.**

For every GitHub issue, create exactly one dedicated branch and open exactly
one pull request.

- If additional comments or follow-up requests arrive on the **same** issue,
  push the follow-up work to that **same existing branch/PR** (the PR updates
  automatically). Do not create a new branch or a new/stacked PR for it.
- Different issues must always use separate branches and separate PRs.
- Do not split one issue's work across multiple PRs, and do not use stacked
  PRs.

Applies from now on; there is no need to retrofit past work.
